1. PRIMARY and MEAN are bit-for-bit identical between the formal library
   scripts and the local-kit runner (identical(data.frame) == TRUE). The
   library's Entrez->SYMBOL de-duplication fix has no numerical effect on
   this reference (4996 mapped rows, 0 duplicate symbols).
2. MINCT2 differed BEFORE the fix: formal 0/0 significant, local-kit 1/0.
   Diagnosis (results/tables/_minct2_order_diagnosis.txt): both scripts
   select the same 921 genes / 262 overlapping genes with IDENTICAL logFC
   values, but order them differently (tapply-sorted vs $candidates order).
   All 100 reference columns contain ties (median 95 tied values among the
   262 genes), so the KS running sum and the permutation null become
   order-dependent. The 'epothilone' nominal hit disappears on a pure gene
   reordering. After aligning the local runner to formal order, scores,
   q_values and significance match and BOTH report 0 significant; only 2
   p_value rows differ by one permutation count (--fast tie boundary).
3. Consequence: all nominal hits in these subset runs are unstable -- to
   n_perm (1000/2000/3000), to aggregation (absmax/mean), and now to gene
   ordering. They are FRAGILITY findings, NOT connectivity discoveries.
   Recommended future hardening: sort the final query vector by gene name
   in BOTH runners before audit_connectivity(); not applied here so the
   formal §3 commands stay verbatim.
4. The full EH3226 lincs.h5 / 45956-signature matrix is STILL NOT in the
   library or on this machine. Full-library §3 rerun remains pending.
